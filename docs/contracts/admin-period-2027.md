# Consultas administrativas por edição e período

F2-4 SQL adiciona ao fim dos parâmetros atuais `p_edition_id uuid default null,p_start_at timestamptz default null,p_end_at timestamptz default null` nas sete RPCs: admin_score_evolution, admin_segment_breakdown, admin_cohort_retention, admin_intel_insights, admin_score_distribution, admin_performance_by_area e admin_performance_by_theme. Preservar defaults antigos, colunas atuais, capability intel.view e ACL; sem overload ambíguo. admin_score_evolution acrescenta edition_id/edition_code/edition_label para distinguir sequência1 em duas edições.

Nulls preservam visão cumulativa legada, com as correções necessárias para não comparar provas de edições diferentes. Edição explícita limita todas as subqueries de tentativas/histórico/AQR/simulados antes de latest/agregação/limite. p_simulado_id de outra edição resulta vazio/zeros coerentes, nunca ignorar o filtro pedido. Período é [start,end), qualquer extremo opcional, inválido start>=end falha22023. Filtra tentativas por started_at (fallback created_at quando necessário); cohort_month continua sendo cadastro do perfil em America/Sao_Paulo. Intervalo explícito substitui a janela automática p_months para a população da coorte.

População de usuários para segmento/coorte em edição explícita: alvo explícito naquela edição OU participação naquela edição, contada uma vez; não atribuir indecisos sem atividade à edição corrente por fallback. Numeradores limitam atividades daquela edição/período; perfil criado antes do período pode participar nas métricas de participação, sem mudar seu mês original na análise de coorte. Null mantém população antiga e exclusão de contas internas. Candidatos por usuário, tentativas por modalidade conforme semântica original; não alterar silenciosamente treino válido/iniciado nem status nos defaults legados.

Séries de médias continuam percentuais brutos dentro de cada edição. Evolution ordena edição/sequence/id, nunca junta por sequence_number de edições distintas. Insigths de queda de nota/participação só comparam provas da mesma edição; se escopo null contém várias edições, suprimir essas comparações ambíguas (ou retornar uma por edição com IDs e rótulos distintos), documentando. Não mascarar erro SQL como insight vazio por exceptionwhenothers. Relatórios autorizados de admin podem usar preview; não estender esse acesso ao aluno ou mudar gates das RPCs públicas.

Frontend posterior aplica seletor global no AdminPeriodContext e opt-in de args atrás de editions_ui; esta entrega SQL não altera UI, sessões presenciais, reprocessamento ou finalizadores. Migration intrinsicamente atômica/reaplicável, checkpoint privado de funções/ACLs e rollback não destrutivo; sem aplicação de produção.
