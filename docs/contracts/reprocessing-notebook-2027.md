# Reprocessamento e paginação do caderno

F2-5: `admin_reprocess_simulado(p_simulado_id uuid,p_reason text) returns jsonb`. Motivo obrigatório. Requer simultaneamente content.manage e attempts.manage (admin atual; suporte/editor isolados não bastam). Recalcula apenas tentativas submitted/expired com resultados completos e janela encerrada, a partir do gabarito atual validado. Não altera o gabarito, reabre/finaliza tentativas, muda modalidade, timestamps/deadline, elegibilidade ou snapshots. Prova em execução/inconsistente é recusada antes de qualquer write.

Ordem validada nos incidentes S5/S6: AQR correct_option_id/is_correct/was_answered → attempts totais/score bruto → histórico → recalculate_user_performance por usuário → reconciliação de entradas existentes no caderno. Ranking é consulta/view; não reter cache incorreto. Não usar finalize_attempt_with_results, que tem early return em tentativa finalizada. Não inventar TRI/pesos oficiais. Escores são percentuais brutos da prova real.

Cada operação mantém checkpoint privado, com ACL/RLS, e auditoria identificada por UUID, motivo, hash do gabarito e contagens antes/depois. Repetir mesmo gabarito é idempotente nos dados; falha em qualquer estágio reverte também auditoria/checkpoints. Locks coordenam gabarito/conteúdo/finalização, sem lock global de todos os usuários. Dados detalhados de alunos não saem no JSON: {operation_id,simulado_id,answer_key_hash,attempts_processed,scores_changed,entries_reconciled,idempotent}. Caderno só reconcilia entradas já associadas à questão/usuário afetado; preservar notas, revisões, histórico e exclusões voluntárias. Se soft-delete de erro obsoleto é usado, marcar origem do reprocessamento para não ressuscitar exclusão manual nem perder reversão de um gabarito corrigido novamente.

F2-7 SQL: `list_error_notebook_page(p_edition_id uuid default null,p_limit integer default 50,p_offset integer default 0) returns jsonb`, caller inferido de auth.uid e PRO. Retorno {items:[],total:integer,limit:integer,offset:integer}; itens mantêm campos de error_notebook e acrescentam edition_id/code/label reais pelo simulado/questão. `get_error_notebook_counts(p_edition_id uuid default null) returns jsonb` retorna {total,mastered,due,by_area}; contagens e lista usam exatamente o mesmo escopo autorizado/soft-delete/liberação. Não aceitar user_id arbitrário ou service token fingindo aluno.

Null = caderno cumulativo, incluindo entradas manuais legítimas sem edição. Filtro explícito exclui sem vínculo, outras edições e questões inconsistentes com simulado; nenhum fallback para alvo ou ano. Treino liberado permanece parte do aprendizado. Questões/indicadores de correção vinculados a prova não liberada não podem vazar por JSON/counts. Limites 1..100, offset não negativo, ordem created_at desc,id desc, sem teto total do PostgREST de1000. As listas de revisão/SRS e os dados antigos não são reescritos pela paginação. Contador1500 exige COUNT no banco, nunca items.length.
